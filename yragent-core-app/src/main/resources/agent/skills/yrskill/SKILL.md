# yrskill — 以人为本独立协议

## 一、触发条件

**触发：**
- 任务涉及文件写入/删除/修改
- 任务涉及执行命令（Shell/编译/安装）
- 任务范围模糊，用户描述少于 20 字
- 任务涉及破坏性操作（删除/格式化/覆盖已有文件）

**不触发：**
- 纯问答（"这段代码什么意思"）
- 纯读取（read_file/list_dir，无后续写入）
- 用户明确说"直接做""不用确认""跳过门禁"

---

## 二、核心协议（6步）

```
[1] 分析现状 → 读取项目 → 12维度评分 → 输出"项目详细现状报告"
[2] 定方案    → 为什么这么做 + 备选方案对比 → 输出"开发计划"
[3] 执行前门禁 → [必须停止] 展示计划 + 代码证据 + 等待确认
[4] 执行      → 逐步执行，每步记录结果
[5] 审查      → 自检产出 + 更新12维度评分 → 输出"编码报告"
[6] 完工门禁   → [必须停止] 确认开发者理解产出 → 通过则完成，不通过回到[2]
```

---

## 三、停止规则

| 情况 | 行为 |
|------|------|
| 规划完成后 | **[必须停止]**，展示计划，等确认 |
| 危险操作前 | **[必须停止]**，明确告知操作和后果 |
| 置信度低时 | **[必须停止]**，诚实说明不确定 |
| 完工后 | **[必须停止]**，确认开发者理解 |
| 纯读取 | 可以不停 |
| 用户说"继续""不用问" | 可以不停 |

---

## 四、12+1 维度评判体系

对项目每个阶段的产出，从以下维度评分（0-10）。**未实施的维度必须标记为 N/A，不得编造。**

| # | 维度 | 评判内容 | 关键文件 |
|---|------|---------|---------|
| 1 | 链路追踪 | 请求/任务全链路是否可追溯 | TraceRecorder, StageOrchestrator |
| 2 | 策略核心 | 核心架构决策是否有文档支撑 | CLAUDE.md, 计划文档 |
| 3 | 上下文管理 | 跨阶段/跨轮次状态如何传递 | TaskExecutionContext |
| 4 | 记忆系统 | 短期/长期记忆是否持久化 | MemoryService, MemoryRepository |
| 5 | 工具调用 | 工具注册/发现/执行/回退机制 | UnifiedToolExecutor, ToolRegistry |
| 6 | 规划推理 | 任务拆解和方案生成的逻辑 | PlanningStageHandler, PlanDocument |
| 7 | 编排协作 | 多步骤/多Agent之间协调 | StageOrchestrator, WorkflowEngine |
| 8 | 安全护栏 | 权限控制/路径沙盒/输入校验 | PolicyEngine, LocalToolExecutor |
| 9 | 可观测性 | 日志/指标/告警覆盖度 | StageGateEngine, stageNotes |
| 10 | 成本配额 | Token消耗/API调用次数控制 | LlmClient 调用统计 |
| 11 | 会话连接 | 前后端通信/状态同步机制 | TaskController, index.html |
| 12 | 技能插件 | 可扩展能力模块的加载 | SkillRegistry, YamlSkillLoader |
| 13 | 错误恢复 | 失败检测/重试/降级/补偿 | CoverageReviewStep, fallback |

**规则**：
- 每项 0-10 分，附带评分依据（"为什么打这个分"）
- 未实现的维度给 N/A，说明"项目中未涉及"
- 评分后给一个总体评价 + 最大短板 + 最优先改进项

## 五、四份报告模板

### 报告一：项目详细现状报告（步骤 [1] 产出）

```
## 项目详细现状报告

### 项目结构速览
[目录结构树 + 每个关键类的一句话职责说明]

### 12维度评分
| 维度 | 评分 | 依据 | 建议 |
|------|------|------|------|
| 链路追踪 | 7/10 | 有TraceRecorder但缺端到端追踪 | 加日志聚合 |
| ... | ... | ... | ... |

### 总体评价 + 最大短板 + 最优先改进
```

### 报告二：开发计划（步骤 [2] 产出）

```
## 开发计划

### 当前任务目标
### 方案选择 + 为什么这么做
### 备选方案对比（至少1个备选）
| 方案 | 优势 | 劣势 | 为什么选/不选 |
### 分步实施
| 步 | 目标 | 工具 | 产出 | 风险 |
### 预估轮次 + 复杂度
```

### 报告三：阶段门禁交流报告（步骤 [3] 产出）

```
## 阶段门禁交流报告

### 当前阶段 + 目标
### 涉及的关键文件
| 文件 | 作用 | 本阶段的行为 |
### Checklist 对照
| # | 检查项 | 代码证据 | 状态 |
### 开发者确认
[等待开发者用自己话复述理解]
```

### 报告四：编码报告（步骤 [5] 产出）

```
## 编码报告

### 本轮改动
| 文件 | 操作 | 说明 |
### 12维度评分更新（与上一轮对比）
| 维度 | 上轮 | 本轮 | 变化原因 |
### 测试结果
### 遗留问题
```

## 六、提问模板

**展示计划时：**
> "我将创建以下文件：[列表]。步骤是：[1][2][3]。使用的工具是：[工具名]。主要风险是：[风险]。[必须停止]你确认继续吗？"

**方案有分歧时：**
> "有两种实现方式：A：[做法+优劣]，B：[做法+优劣]。我推荐 A，原因是：[原因]。你的选择？"

**置信度低时：**
> "我不确定 [具体事项]，目前基于 [假设] 推进。如果这个假设不对，请纠正我。"

**完工确认时：**
> "本轮完成了 [产出]。现在我需要确认：你理解我做了什么吗？能用你自己的话复述一下本轮的核心改动吗？"

---

## 七、多轮循环

每轮结束自问：
- 计划中的步骤都完成了吗？
- 产出和用户最初的目标一致吗？
- 12维度的评分有提升吗？
- 如果完成 → [6] 完工门禁
- 如果未完成 → 生成下一轮计划 → [2]

最多 10 轮，超出强制完工门禁。

---

## 八、禁止行为

- 规划后不展示就直接执行
- 把"好的""可以""随便"当作充分确认
- 危险操作前不再次确认
- 假装高置信度（不确定时必须诚实说）
- 编造12维度评分依据（没看到的代码就说 N/A）
- 跳跃步骤（不能从[1]直接到[4]）
